There are two ways to run a bot: **long polling** (your bot pulls updates from Telegram) and **webhooks** (Telegram pushes updates to your server). Handlers are identical in both modes — you only change how the bot starts.

## Long Polling

The simplest way to run a bot. No public URL, no SSL certificate — works from your laptop, a VPS, or a container:

```typescript
import { createBot } from "@effect-ak/tg-bot"

const instance = await createBot()
  .onMessage(({ text }) => [text(({ payload, ctx }) => ctx.reply(payload.text!))])
  .run({ bot_token: "YOUR_BOT_TOKEN" })
```

### How It Works

<Steps>

1. A user sends a message to your bot.

2. Telegram stores the update in a queue, where it waits for up to 24 hours.

3. The bot runner polls the queue with the `get_updates` method, holding each request open until updates arrive (long polling).

4. The runner picks the first matching handler and invokes it with the update.

5. The handler returns a `BotResponse`, and the runner sends it back to Telegram.

</Steps>

Up to 10 updates are processed concurrently. If one handler fails, the others keep running.

### Stopping the Bot

`bot.run()` returns a `BotInstance` with a `stop()` method that aborts the polling loop:

```typescript
const instance = await bot.run({ bot_token: "YOUR_BOT_TOKEN" })

// Later — gracefully stop
instance.stop()
```

### Hot Reload

Replace handlers without restarting the process — the next polling iteration picks up the new behavior. This is how the [Playground](/playground/) applies your code changes instantly:

```typescript
instance.reload({
  type: "single",
  on_message: [{ handle: ({ ctx }) => ctx.reply("Updated handler!") }]
})
```

## Webhooks

For serverless deployments (Cloudflare Workers, Vercel, AWS Lambda, `Bun.serve`), use `.webhook()` instead of `.run()`. It returns a handler that accepts a standard `Request` and returns a `Response`:

```typescript
import { createBot } from "@effect-ak/tg-bot"

const handler = createBot()
  .onMessage(({ command }) => [command("/start", ({ ctx }) => ctx.reply("Hello!"))])
  .webhook({
    bot_token: "YOUR_BOT_TOKEN",
    secret_token: "YOUR_WEBHOOK_SECRET"
  })

// Export as your HTTP handler
export default handler
```

You can also process a raw `Update` object directly (this skips the secret token check — use it only when your platform has already authenticated the request):

```typescript
await handler.handleUpdate(update)
```

### Secret Token

A webhook URL is not a credential — `*.workers.dev` and similar hostnames are guessable, and URLs leak into logs and error reporters. Anyone who learns the URL can POST a forged `Update` and drive your bot as any user.

Telegram solves this with a **secret token**: you pass it to `set_webhook`, and Telegram sends it back on every delivery in the `X-Telegram-Bot-Api-Secret-Token` header. When you set `secret_token` in `.webhook()`, the handler rejects requests whose header is missing or different with `403 Forbidden` before parsing the body. The comparison is constant-time.

The token is any string of 1–256 characters from `A-Z`, `a-z`, `0-9`, `_` and `-`. Generate one and keep it next to your bot token:

```bash
openssl rand -hex 32
```

:::caution
`secret_token` is optional for backward compatibility, but the handler logs a warning when it is omitted. Treat it as required for anything public.
:::

### Registering the Webhook

Telegram needs to know where to push updates. The handler exposes `setWebhook()`, which calls [`set_webhook`](/api/methods/set-webhook/) with the same `secret_token` the handler verifies — so both ends always agree:

```typescript
await handler.setWebhook({
  url: "https://your-app.example.com/webhook",
  allowed_updates: ["message", "callback_query"]
})
```

Call it once after deploying (from a script, a protected `/setup` route, or a CI step). To switch back to long polling, remove the webhook with [`delete_webhook`](/api/methods/delete-webhook/).

### Cloudflare Workers Example

Secrets come from `env`, which is only available inside `fetch`, so build the handler there — it is cheap (no connections are opened until an update arrives):

```typescript
import { createBot, SECRET_TOKEN_HEADER } from "@effect-ak/tg-bot"

interface Env {
  BOT_TOKEN: string
  WEBHOOK_SECRET: string
}

const bot = createBot().onMessage(({ command }) => [
  command("/start", ({ ctx }) => ctx.reply("Hello from Workers!"))
])

export default {
  async fetch(request: Request, env: Env): Promise<Response> {
    const webhook = bot.webhook({
      bot_token: env.BOT_TOKEN,
      secret_token: env.WEBHOOK_SECRET
    })

    const url = new URL(request.url)

    // One-off registration: GET /setup, protected by the same secret
    if (request.method === "GET" && url.pathname === "/setup") {
      if (request.headers.get(SECRET_TOKEN_HEADER) !== env.WEBHOOK_SECRET) {
        return new Response("forbidden", { status: 403 })
      }
      await webhook.setWebhook({ url: `${url.origin}/webhook` })
      return new Response("webhook registered")
    }

    if (request.method === "POST" && url.pathname === "/webhook") {
      return webhook(request)
    }

    return new Response("not found", { status: 404 })
  }
}
```

Deploy and register:

```bash
wrangler secret put BOT_TOKEN
wrangler secret put WEBHOOK_SECRET
wrangler deploy
curl -H "X-Telegram-Bot-Api-Secret-Token: $WEBHOOK_SECRET" https://<worker>.workers.dev/setup
```

A complete, deployable demo — one Worker hosting several demo bots with an inline menu to switch between them, state in KV — lives in [`example`](https://github.com/kondaurovDev/tg-bot-sdk/tree/main/example). Its README walks through `wrangler login` → secrets → `deploy` → `/setup`.

### Platforms Without a `Request` Object

Some runtimes (Express, AWS Lambda with API Gateway, Vercel's Node functions) hand you a parsed body instead of a `Request`. Verify the header yourself and call `handleUpdate`:

```typescript
import { createBot, SECRET_TOKEN_HEADER } from "@effect-ak/tg-bot"

const bot = createBot()
  .onMessage(({ command }) => [command("/start", ({ ctx }) => ctx.reply("Hello!"))])
  .webhook({ bot_token: process.env.BOT_TOKEN!, secret_token: process.env.WEBHOOK_SECRET! })

app.post("/webhook", async (req, res) => {
  if (req.get(SECRET_TOKEN_HEADER) !== process.env.WEBHOOK_SECRET) {
    return res.status(403).send("forbidden")
  }
  await bot.handleUpdate(req.body)
  res.status(200).send("ok")
})
```

## Poll Settings

Customize polling behavior via the `poll` option:

```typescript
createBot()
  .onMessage(/* ... */)
  .run({
    bot_token: "YOUR_BOT_TOKEN",
    poll: {
      log_level: "debug",
      on_error: "continue",
      batch_size: 50,
      poll_timeout: 30,
      max_empty_responses: 5
    }
  })
```

| Option                | Default     | Description                                                     |
| --------------------- | ----------- | --------------------------------------------------------------- |
| `log_level`           | `"info"`    | `"info"` — basic logging, `"debug"` — all updates and responses |
| `on_error`            | `"stop"`    | `"stop"` — stop bot on error, `"continue"` — keep polling       |
| `batch_size`          | `10`        | Updates per poll (10–100)                                       |
| `poll_timeout`        | `10`        | Long polling timeout in seconds (2–120)                         |
| `max_empty_responses` | `undefined` | Stop after N consecutive empty responses (useful for testing)   |

## Custom Client

Both `run()` and `webhook()` accept a `client` instead of `bot_token`. Anything
with the `TgBotClient` shape works — a client you built with custom `fetch`,
`base_url` or timeouts, or the in-memory emulator for tests:

```typescript
import { makeTgBotEmulator } from "@effect-ak/tg-bot-emulator"

const emulator = makeTgBotEmulator()

const instance = await createBot()
  .command("/start", ({ ctx }) => ctx.reply("Welcome!"))
  .run({ client: emulator.client })

emulator.sendMessage("/start")
const reply = await emulator.nextBotMessage() // { text: "Welcome!", ... }
```

`bot_token` and `client` are mutually exclusive. See [Testing Bots](/bot-runner/testing-bots/)
for the full emulator API.

## Polling vs Webhooks

|          | Long Polling                    | Webhooks                      |
| -------- | ------------------------------- | ----------------------------- |
| Setup    | No public URL needed            | Requires HTTPS endpoint       |
| Hosting  | Any machine, VPS, local dev     | Serverless / always-on server |
| Latency  | ~1s polling interval            | Instant push from Telegram    |
| Best for | Development, simple deployments | Production, serverless        |

A common path: develop with long polling, deploy to serverless with webhooks — your handlers don't change.
